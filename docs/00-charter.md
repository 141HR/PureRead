## 1. 项目愿景与定位

本项目旨在构建一款面向 **Windows + Android** 双端用户的开源跨端阅读器。

网文与本地长篇阅读领域长期存在体验割裂：移动端已有成熟的书源阅读生态，但 Windows 桌面端往往缺乏排版考究、大文件流畅、且能与手机端无缝衔接阅读进度的轻量客户端。本项目坚持 **“一套代码覆盖双端、极致排版与翻页质感、书源引擎解耦可扩展”** 的工程原则，先通过本地大 TXT 与自研排版内核打磨核心阅读体验，再叠加统一抽象书源与无服务器多端同步。

---

## 2. 范围边界（In-Scope vs Non-Goals）

### 2.1 In-Scope（计划覆盖范围）
- **目标平台**：Windows 桌面端 + Android 移动端（基于同一套 Flutter 代码库构建与发布）。
- **本地阅读能力**：`v0.1` 支持本地超大 TXT 文件（数十 MB 级别）流式识别编码、按章节字节偏移建索引、秒开与低内存分片读取；`v0.3` 纳入本地 EPUB 解析（`LocalEpubProvider`）。
- **极致阅读体验**：自研分页排版引擎（基于字符偏移 `charOffset` 精准定位）、中文标点避头尾、中英混排间距、自定义字体与主题、桌面双栏与快捷键、移动端多模式翻页与音量键翻页。
- **统一书源架构**：采用顶层统一 `BookProvider` 契约，支持 **本地 TXT 驱动**、**本地 EPUB 驱动（`v0.3`）**、**轻量化 JS 插件书源驱动** 与 **渐进式 Legado JSON 书源兼容驱动**，并配备统一正文净化管道。
- **单机备份与数据安全**：支持本地整库备份包（`.pureread.zip`）导出与恢复；数据库层预留 `charOffset`、`updatedAt`、`deviceId` 等扩展字段，为未来扩展同步保留零重构路径。

### 2.2 Non-Goals（v1.0 明确不做）
- **内容与合规红线**：软件本身为纯阅读与解析工具，**不内置任何小说内容、不内置任何默认盗版书源**。
- **跨端自动同步**：`v1.0` **暂不做 WebDAV / 局域网直连等双端同步功能**（已移至 `v1.0+` 远期规划）。
- **账号与商业托管**：`v1.0` 不自建后端服务器、不设用户账号体系、不提供云存储托管或商业变现模块。
- **远期延后功能**：`v1.0` 暂不包含 TTS 语音听书、社区书评/弹幕、复杂富媒体学术 PDF 批注能力。
- **全量 Legado 兼容承诺**：不承诺第一版 100% 兼容所有依赖重度前端渲染或复杂反爬机制（如 `webView: true`、人机挑战）的 Legado 书源；优先保证常规源可用与异常隔离。

## 5. Phase 0 技术探针（PoC）验收计划

在进入大规模业务编码之前，先用限时独立原型（Spike）验证两个核心风险点：

1. **PoC-1：大 TXT 索引与自研分页渲染探针**
   - **目标**：验证 30MB 中文长篇 TXT 的编码探测（UTF-8 / GB18030）与流式章节扫描速度，以及基于 `TextPainter` + Isolate 后台预排版的分页准确性与翻页帧率。
   - **验收标准**：Windows 与 Android 真机（或模拟器）上首次建索引耗时 < 2s；字号切换与窗口缩放前后，通过 `charOffset` 可精确还原同一句话且零丢字、零重字；连续翻页维持 ≥ 60fps。
2. **PoC-2：统一 `BookProvider` 与 JS 沙箱探针**
   - **目标**：验证 Flutter 侧嵌入式 JS 引擎（如 QuickJS）在 Windows 与 Android 双端的编译、运行时稳定性及与 Dart 异步 HTTP 请求桥接能力。
   - **验收标准**：在统一 `BookProvider` 接口下，使用本地离线 HTML/JSON 快照及单个测试站点，分别跑通 1 个轻量化 JS 书源与 1 个基础 Legado JSON 书源的“搜索 → 目录 → 正文”全链路。
